Finite State Machine Specification

Formal state machine definitions and transition semantics

3 Defined States
UNKNOWN Initial State

Assigned automatically to any newly added server or when no connectivity checks have been executed yet.

  • Next State: Transitions to HEALTHY upon first 2xx HTTP response.
  • Next State: Transitions to DOWN if first check fails, times out, or returns non-2xx.
HEALTHY Operational State

The server successfully responded to the HTTP request with a standard successful status code (200–299).

  • Next State: Maintains HEALTHY if subsequent check returns 2xx.
  • Next State: Transitions to DOWN immediately if request times out or returns error.
DOWN Failure State

The server failed to respond within timeout window, connection was refused/unreachable, or returned an error status code.

  • Next State: Transitions to HEALTHY once a check successfully yields 2xx (Recovery).
  • Next State: Maintains DOWN as long as errors persist.

FSM State Transition Matrix

From State To State Trigger Condition FSM Action & Logging
UNKNOWN HEALTHY First HTTP health check succeeds with 2xx status code Server marked Healthy; latency and status recorded to MongoDB.
UNKNOWN DOWN First check fails, times out (>5000ms), or returns non-2xx Server marked Down; error details and timestamp stored.
HEALTHY DOWN Server experiences outage, timeout, connection drop, or HTTP 4xx/5xx Health degradation detected; transition event flagged in history.
DOWN HEALTHY Server recovers and returns successful 2xx response Server recovery logged; availability recalculated.
HEALTHY HEALTHY Subsequent check continues returning 2xx State maintained; latest response time updated.
DOWN DOWN Subsequent check continues failing or timing out Failure state maintained; error timestamp logged.
